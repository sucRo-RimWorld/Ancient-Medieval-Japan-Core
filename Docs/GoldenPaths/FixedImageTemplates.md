## 必須方針

同じパーツを使う画像は、承認済みパーツの画素を再利用する。生成モデルへの「同じにする」という指示、参照画像編集、見た目の比較だけではピクセル一致を保証できない。生成は変更部分の素材作成に限定し、最終画像は固定マスターから決定的に合成する。

対象はWorkshop表紙の共通タイトル・装飾・背景、枡などの共通容器、同じ道具・部材、同一個体の状態差分など。**同じ画風**と**同じパーツ**は区別する。別樹種のシルエットまで同一にする必要はない。同一の幹を再利用すると宣言した場合、その可視部分は固定する。

## テンプレート登録

各系統の所有リポジトリを登録簿の正本とし、次を登録する。バイナリの固定マスター/マスクは原則として所有リポジトリに置く。ただし、ChatGPTの別チャット間で同じ実画像を共有するため persistent Library をバイナリ正本として使う系統では、所有リポジトリに **Libraryの完全パス・寸法・SHA-256・マスク意味・合成/検証手順を含むJSONマニフェスト** を必ず置き、取得不能時はBLOCKEDとする。この条件を満たさないものを「固定済み」と報告しない。

- 承認済み固定マスター（可逆PNG）。元画像がJPEGなら一度だけデコードしてPNG化し、そのRGBAを基準とする。JPEGを繰り返し保存しない。
- 同寸法の8-bitグレースケールPNGマスク。0=保護、255=変更可能。中間値は禁止。輪郭のアンチエイリアスも保護画素に含める。
- JSONマニフェスト：系統ID・版・承認根拠・元画像の所在/コミット・寸法・マスターとマスクの相対パスおよびSHA-256・変更範囲の意味・固定レイヤー順。
- **可変内容物を持つ系統では承認済み完成例（filled exemplar）も必須。** 共通パーツの画素が固定されていても、キャンバス上の大きさ・余白・内容物の充填量・高さ・前後関係が承認例から外れていればテンプレートは未完成とする。完成例の所在・SHA-256・基準寸法・外接bbox等をマニフェストへ記録する。
- テンプレートを `active` にする前に、少なくとも1つの代表的な完成派生を実際に合成し、固定画素検査に加えて256pxとゲーム相当の縮小表示で作者承認を得る。空マスター単体の承認だけでは量産開始しない。
- 必要な前景/後景の固定レイヤー、共通フォント・文字配置等の設定、派生画像の所在。

マスクは単なる左右の矩形分割とは限らない。枡のv4契約では下側のHardFixedを保護し、内壁・縁・前壁上部・側壁上部をContactZoneとして遮蔽・接触部編集を許可する。突出は独立ExtensionAllowed内だけとし、完成例のalphaで全資源を制限しない。表紙は右の図案領域とAddon名の文字領域だけ変更可能とし、共通タイトル・装飾・それ以外の背景を保護する。マスクを広げて差分検査を通す行為は禁止。

可変部分を取り除く必要がある場合は、最初に一度だけ空のマスターを作成・確認して登録する。既存Core図案やAddon名が残る完成表紙に新図案を上書きするだけではテンプレート完成とは扱わない。

新規系統/マスター変更は承認を記録して新しい版にする。既存の承認済み提案・マスターは毎回再承認を求めず使用する。マスター・マスクを派生ごとに変更しない。

登録前の客観的な品質不良（拡縮ジャギー、補間荒れ、ハロー、継ぎ目、切れ、別レイヤーの残骸、誤った占有率など）はエージェント側で検出・修正する。既に承認された構図・形状・色方針を変えない技術的クリーンアップは再承認待ちにせず実施し、既知の修正可能な欠陥を残したまま「妥協可能か」を作者に判断させない。新しい意匠・形状・構図へ変える場合のみ通常の承認手順へ戻る。

汚染経路が判明した場合（誤った参照画像、誤った固定パーツ、旧/不正マスク、全体再生成の混入、誤色・境界色の伝播等）は、その時点以降の派生物をすべて失効扱いとし、Library・ローカル作業領域の候補/比較画像/プレビューを削除する。「比較に使えるかもしれない」という理由で保持しない。正本マスター・正本参照・マニフェストのみを残し、そこから再開する。診断用に残す必要がある場合は production source と混同できない隔離名/場所で保持し、正本参照経路から到達できないようにする。

固定テンプレートで前後関係を持つ共有部品は、単一の内部editable maskで可変素材を切り抜かない。枡では正本全体を保持した描画コンテキスト上で内容物と接触部を扱い、下側のHardFixedだけ直接復元する。上部接触帯は遮蔽可能とし、相補的な前後ラスター分割や全面的な前縁復元は行わない。空scaffoldのRGBAが正本と0差分であることに加え、別形状でも自然な前後関係が成立することを検証する。領域マスクは契約の検査用であり、不正な内容物を切り抜いて合格させる道具にしない。

## 用語上の実行ルール

AMJ画像作業では、ユーザーの「作成」「制作」「続けて」を画像生成の許可と解釈しない。これらは登録済みマスター・マスク・ローカル処理・決定的合成・検証による制作継続を意味する。

ImageGenを使用してよいのは、ユーザーが明示的に「生成」と指示し、かつ対象Golden Pathが新規生成を許可する場合だけとする。固定テンプレート系では、その場合も可変素材だけを生成し、共通パーツまたは完成画像全体を生成しない。

ローカル/決定的な経路で制作できず、新規生成が必要だがユーザーが「生成」と指示していない場合は、無断で生成へ切り替えずBLOCKEDとして不足素材を明示する。

## 制作と検査

1. 対象のAGENTSとmain Coordination、系統の正式仕様、本書を読む。
2. 実際の承認済み画像を開き、テンプレートID/版、ハッシュ、固定範囲・変更範囲を確認する。取得できなければ推測で共通部分を再生成せず、所有リポジトリにBLOCKEDを記録する。
3. 変更部分だけを生成/描画する。全体画像が生成された場合も、その共通部分は採用しない。
4. 通常の系統は可変素材だけを位置・サイズ調整し、テンプレートと同寸法の透明RGBAレイヤーに配置する。枡v4は例外として、完全なマスターscaffoldを保持した描画済みコンテキスト画像を入力し、内容物と接触部を一緒に編集する。固定パーツに拡縮・回転・色補正・ぼかし・再描画・全体量子化を適用しない。
5. 所有リポジトリに登録したマスター/マスクで合成する。常に手前のHardFixedだけ内容物より手前へ復元する。接触帯を前面であることだけで固定しない。最終的にすべての保護画素をマスターから直接コピーする。
6. 最終PNGを再デコードし、保護範囲の**RGBA全4チャンネル差分が0画素**であることを機械的に検査する。透明画素のRGBも比較する。差分1画素でも不合格。目視類似や許容誤差で代替しない。
7. 所有リポジトリのPNG構造/CRC/デコード検査も実行する。画素一致検査とファイル整合性検査は別物。
8. 可変部分の見た目・内容・小サイズでの読みやすさを確認し、成果物とテンプレートID/版・ハッシュ・検査結果を記録する。コミット後の取得済みPNGにも検査を適用する。

可逆PNGと登録寸法が正本。別サイズが必要なら系統全体で一度作った別サイズのマスター/マスクを登録してから合成する。最終画像全体の縮小・JPEG化後に同一画素を保証したと主張しない。外部サービスでのサムネイル変換はこの保証の対象外。

## 共通ツール（Core所有）

依存：Python 3 + Pillow。`Scripts/Art/fixed_template.py` はハッシュを照合し、マスク外の変更を拒否する。別リポジトリからもCoreのこのツールを使い、競合する独自ルールを作らない。

最小マニフェスト形式（ハッシュは実ファイルから採る。以下は形式説明であり登録済みテンプレートではない）：

```json
{
  "version": 1,
  "family": "approved-family-id",
  "template_revision": "v1",
  "size": [256, 256],
  "master": {"path": "master.png", "sha256": "actual SHA-256"},
  "editable_mask": {"path": "editable-mask.png", "sha256": "actual SHA-256"}
}
```

```bash
python Scripts/Art/fixed_template.py compose path/template.json path/variable.png --output path/final.png
python Scripts/Art/fixed_template.py validate path/template.json path/final.png
python Tests/test_fixed_template.py
python Tests/validate_png_assets.py
```

通常の固定マスク系統のvariable.pngは登録寸法に配置済みの透明レイヤー。枡v4では完全なマスター文脈を保持した内容物＋接触部画像を使い、系統Golden Pathの検証専用入口から開始する。ツールは自動拡縮しない。通常の系統はマスク内をalpha合成し、マスク外のRGBAをマスターからコピーする。枡v4は描画済み画像のHardFixedだけ直接復元し、それ以外の不正な変更は拒否する。空マスター/マスクの適切さは系統の仕様と画像確認で担保する。ツール単体のPASSはテンプレートの承認や全既存画像の適合を意味しない。

## 今後の新しい共通パーツ系統への自動適用

今後の画像制作では、生成前に既存画像との共通パーツの有無を確認する。新しい共通パーツまたは画像系統が生まれた場合、ユーザーから個別のルール追加指示を待たず、本方針をその系統に適用する。

最初の承認済み画像から、次の派生制作前に固定マスター・変更可能マスク・ハッシュ付きマニフェストを登録する。系統の正式な画像仕様/Golden Pathに、共通部分、変更範囲、正本のパス、版、合成順序、検査コマンドを追記し、AGENTSまたは画像制作入口から参照できる状態にする。派生の固定RGBA差分0画素検査を制作・統合手順へ追加し、継続利用する系統は登録済み派生を検査する自動ゲート/CIに組み込む。

完了条件は「画像完成」だけでなく「再利用可能な固定テンプレート登録・正式手順への追記・画素一致検査の実装/実行」までとする。登録未完了なら未完了としてmain Coordinationに記録する。共通パーツのない単独画像や画風だけが同じ別形状には、不要な画素固定を課さない。承認済み仕様を使用する際に再承認は求めず、新しい視覚仕様/マスター変更に必要な承認のみ既存の手順で扱う。
